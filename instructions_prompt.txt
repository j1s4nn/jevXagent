2. MOST IMPORTANT ARCHITECTURAL RULE
====================================

The system must NOT assume that a standalone daemon automatically sees traffic from every AI coding agent.

A proxy only works when the selected agent actually routes its API requests through the proxy.

Therefore create an abstraction:

Agent Integration Layer

with responsibilities:

1. detect installed agents
2. detect usable agent executable
3. identify supported provider/transport
4. determine how the agent can route API traffic through JevXagent
5. configure routing without modifying agent internals
6. launch or connect to the agent
7. restore temporary environment/configuration when appropriate
8. report unsupported integration clearly

Do NOT assume all four clients use the same API format.

Supported agent candidates:

* Claude Code
* Codex
* Kilo Code
* Cline

The CLI should detect which ones actually exist on the local machine.

If a client is not installed:

* do NOT display it as available
* do NOT fabricate support
* keep it out of selectable integrations

If zero supported agents are found:

* report zero available agents
* exit cleanly

8. LINE-J INJECTION RULE
========================

The request transformation should conceptually be:

ORIGINAL AGENT REQUEST

*

TRUSTED JEV EXECUTION CONTEXT

→

FINAL REQUEST TO MAIN AGENT

The main agent must see the Jev result BEFORE producing output.

Do not make Jev's decision a separate unrelated API call that the main agent cannot see.

Do not call the main model once for Jev reasoning and another time for the same reasoning.

Jev is the fast decision engine.

The main agent is the generation/work engine.

=====================

The CLI must have a Jev ON/OFF control.

* do NOT call Jev

* still collect metrics
* still measure agent latency/tokens

IMPORTANT:

Jev OFF should mean "same agent, no Jev optimization".

Do not change unrelated variables between ON and OFF.

This is necessary to make the comparison meaningful.

14. JEV TIMEOUT / FAIL-OPEN
===========================

The proxy must stay responsive.

Set a strict Jev timeout using the project's async/network architecture.

Target behavior:

Jev fast success
→ continue normally

Jev timeout
→ immediately forward original request to agent
→ mark Jev timeout
→ do not block the user

→ mark Jev error

Jev disabled
→ directly forward original request

IMPORTANT:
